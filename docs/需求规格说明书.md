1. 引言
1.1 目的
本文档为"云南省企业就业失业数据采集系统"项目的需求规格说明文档，旨在明确项目的系统特性、功能性需求、非功能性需求及系统约束条件，为开发团队、测试团队及项目甲方提供统一的开发与验收基准。同时该文档将详细介绍平台的功能、环境、特点、受众情况，可供用户查阅使用。具体目标包括：

定义核心需求：描述系统在全省就业与失业数据监测场景下需实现的核心业务功能（如企业信息备案、月度数据填报、逐级审核退回、多维统计分析与国家系统上报）。

规范系统边界：明确平台支持的软硬件运行环境（如政务云、国产信创适配）、用户角色（省级用户、市级用户、企业用户及系统管理员）及省、市、企三级协同的交互流程。

指导开发与测试：提供详细需求描述，确保开发与测试活动与上级主管部门的业务规范目标一致，避免需求不明确、口径不统一及需求蔓延。

1.2 文档约定

1.4 项目范围
本项目是一款面向云南省全省范围的企业就业与失业情况数据采集与管理平台，旨在建立标准化、信息化、可追踪的数据采集与管理体系。系统集成全省企业基础信息备案、各调查期数据填报与历史数据查询功能；建立省、市、企三级业务协同机制，实现数据从填报、市局初审到省局汇总的闭环管理；为管理部门提供数据汇总、图表分析、多维分析（对比与趋势分析）及数据导出等决策支持；并实现与国家失业监测系统的数据接口规范对接。

本项目明确排除以下范围：

功能限制：不涵盖底层物理硬件设备的部署与日常维护、不包含企业内部的人力资源管理（HR）或企业财务结算业务处理

数据限制：禁止处理与就业失业监测无关的员工个人隐私明细数据（如未脱敏个人生物特征数据）及非结构化原始凭证；所有采集的企业与个人数据仅限在云南省政务云境内存储

兼容性限制：不支持Windows Server 2012以下版本系统、不支持未满足国家信息安全等级保护三级（等保三级）标准的运行环境，核心代码严禁引入未经安全审查的第三方开源组件

2. 总体描述
2.1 产品前景
为及时掌握云南省企业就业与失业情况，规范企业数据采集、审核、汇总、分析和上报流程，有必要建设统一的《云南省企业就业失业数据采集系统》。该系统面向企业用户、省级管理部门和市级管理部门，围绕企业备案、月度数据填报、逐级审核、汇总分析、通知发布及系统管理等业务，建立标准化、信息化、可追踪的数据采集与管理平台。

当前企业就业失业数据的统计工作涉及企业填报、市级审核、省级汇总以及上报部委等多个环节，业务链条较长，参与角色较多，若缺少统一的信息系统支撑，容易出现数据口径不一致、上报不及时、审核效率低、统计分析困难等问题。因此，建设本系统对于提升就业失业数据采集效率、增强数据管理规范性、支撑上级主管部门决策分析具有重要意义。

2.2 项目目标
本系统的建设目标主要包括以下几个方面：

建立统一的企业就业失业数据采集平台，实现企业基础信息备案、月度数据填报和历史数据查询。

建立省、市、企业三级业务协同机制，实现企业上报、市局审核、省局汇总与上报的闭环管理。

提供数据汇总、图表分析、多维分析、数据导出等功能，为管理部门提供统计分析支撑。

通过通知管理、用户管理、角色管理、上报时限管理和系统监控等功能，提升系统运行的规范性和可维护性。

实现与国家失业监测系统的数据接口对接，提高数据共享和上报效率。

2.3 用户类及其特征
本平台主要为政府管理部门提供服务，同时又可为其他非专业人员提供数据处理服务。下表按优先级由高到低的顺序介绍了平台主要的用户类及其特征。

用户类	个人特征	工作特征
省级用户	核心管理人员，具备宏观数据分析与系统管理能力	负责全省企业备案终审、数据汇总分析、图表与多维分析、通知发布及系统权限维护
市级用户	业务审核人员，熟悉当地企业情况与就业政策	负责行政区域内企业填报数据的初审与核实，发布通知，配合省局完成业务协同
企业用户	基层办事人员，具备基础电脑操作能力，关注填报时限	负责维护企业基础信息、完成月度就业失业数据填报、查询历史状态及修改个人信息
系统管理员	具备较强的IT运维能力，熟悉系统架构与数据库安全	负责系统初始化、权限分配、日志监控、接口对接维护及系统整体稳定性保障
2.4 运行环境
本系统采用标准的政务三层架构部署。

硬件层面：系统需运行在支持国际主流x86或国产信创（如鲲鹏、飞腾）芯片架构的服务器上，配备充足的存储空间以支撑全省企业多年的历史就业数据留存。

软件层面：后端采用Java企业级开发平台（Spring Boot 2.7），要求运行环境预装JDK11或更高版本。数据库采用关系型数据库MySQL 8.0（或国产达梦数据库），用于存储业务核心数据。

部署方式：推荐采用Docker容器化技术进行封装，并利用Kubernetes进行集群调度，以确保系统在每月填报高峰期具备良好的负载均衡与容错能力。

2.5 设计和实现上的约束
技术架构约束：

系统需全面适配国产化软硬件环境，包括国产操作系统（如银河麒麟、统信UOS）及国产中间件

核心代码需保持自研可控，严禁引入未经安全审查的第三方开源组件

数据合规要求：

严格遵守《数据安全法》与《个人信息保护法》，所有采集的企业与个人数据仅限在云南省政务云境内存储

涉及敏感字段（如证件号、联系方式）在传输与存储时需进行加密处理

开发资源约束：

系统需满足国家信息安全等级保护三级（等保三级）标准

关键业务接口（如报表导出、批量审核）的响应延迟应控制在500ms以内，确保在全省并发访问时的流畅度

法律要求：

系统建设必须符合云南省关于"就业失业监测"的业务规范，数据上报口径需严格对接国家失业监测系统的标准接口

2.6 假设与依赖
2.6.1 假设
用户操作假设：假设企业端的办事人具备基础的计算机应用能力，能通过浏览器独立完成数据填报工作

业务稳定性假设：假设在系统开发周期内，国家关于就业失业统计的指标体系不发生重大变更

2.6.2 依赖
基础设施依赖：本系统的运行高度依赖云南省政务外网及政务云提供的计算、网络与存储资源

外部数据依赖：企业身份校验功能依赖于省政务公共数据平台提供的企业统一社会信用代码接口；同时，系统的上线运营依赖于省级主管部门下发的业务启动通知及管理办法

3. 系统特性
3.1 企业端：数据采集与备案子系统
3.1.1 描述与优先级
系统特性描述：

本模块面向全省各企业用户，旨在为企业提供一个便捷、规范、安全的数字化工作台。其核心功能不仅涵盖企业基础信息的首次备案与变更申请，还包含按规定调查期进行的数据填报（含暂存与提交）、历史报表流转状态查询、各级政策通知浏览以及账户安全管理等操作。

通过本模块，企业能够及时响应省、市管理部门的数据采集要求，实时掌握本企业的上报进度与审核反馈，确保就业失业监测数据的准确性、合规性与时效性。

优先级： 高

备案审核通过	系统开放数据填报功能
企业用户暂存填报数据	系统保存数据草稿，状态标记为"暂存"，不触发审核流程
企业用户提交数据	系统保存数据并提交至市级审核
数据被退回	系统标记退回状态并提示退回原因

3.1.3 功能需求
本模块需支持企业用户完成备案信息录入、数据填报、数据查询及基础账户管理功能。

备案信息管理： 系统应提供统一的企业信息录入界面，支持企业按照规范填写组织机构代码、企业名称、所属行业、联系方式等信息，并对关键字段进行格式校验，确保数据规范性。企业提交备案信息后，系统应将数据提交至省级审核，并在审核通过后开放数据填报权限。

数据填报： 系统需支持企业在规定调查期内按照模板填报就业失业相关数据，并在保存与提交过程中进行数据合法性校验。当调查期就业人数小于建档期就业人数时，系统应强制要求填写就业人数减少原因及说明；当超过上报时间时，应禁止数据提交。填报完成后，系统应将数据状态标记为"已上报"，并流转至市级审核环节；若数据被退回，系统应明确展示退回原因，并允许企业进行修改后重新提交。

数据查询： 系统需支持企业按调查期等条件查询历史填报数据，查询结果仅支持查看，不允许导出或修改，以保证数据安全性。

通知浏览： 系统应提供通知浏览功能，支持企业查看本级及上级发布的通知信息，包括通知标题、发布时间及具体内容，以保证信息传达的及时性。

账户安全管理： 系统应提供密码修改功能，允许用户在登录状态下修改账户密码，并在原密码校验失败时给予提示；同时，系统应支持"忘记密码"找回功能，用户可通过输入账号、注册手机号或邮箱获取验证码，系统校验账号存在性后发送验证码，用户输入验证码及新密码即可完成密码重置，若验证码错误或超时则提示重新获取，连续多次输入错误验证码时将临时锁定找回操作。

3.2 市级端：数据审核与辖区调度子系统
3.2.1 描述与优先级
系统特性描述：

本模块面向各市级管理部门，旨在为市级用户提供一个高效、可追溯、全局可视的数据审核与管理平台。

其核心功能涵盖企业上报数据的审核与退回、辖区填报进度统计看板、数据导出与退回历史查询，以及通知发布和账户安全管理等操作。

通过本模块，市级用户能够精准把控辖区内企业数据填报进度与质量，及时指导企业完成数据修正，确保就业失业监测数据的准确性、完整性与上报时效性。

优先级： 高

3.2.3 功能需求
本模块需支持市级用户对企业上报数据进行审核、退回及通知管理，并提供辖区填报进度统计、数据导出、退回历史查询及账户安全管理功能。

数据审核： 系统应提供统一的数据审核界面，展示企业填报数据及历史记录，供市级用户进行核查与处理。在审核过程中，用户可对数据执行审核通过或退回操作；当选择退回时，系统必须要求填写退回原因，并将该原因与数据一并记录，同时通知企业用户，以保证审核过程的可解释性与可追溯性。审核通过后，系统应将数据状态更新为"已审核"，并自动上报至省级；退回情况下，数据状态应标记为"退回"，企业需根据退回原因进行修改后重新提交。

统计看板： 系统还应提供统计看板，以图表形式展示辖区企业总数、已报数、未报数、审核通过率等关键指标，便于市级用户直观掌握辖区内企业填报进度与审核质量。

数据导出： 系统应支持按调查期、企业维度导出审核通过的数据为Excel文件，供本地存档或进一步分析。

退回历史查询： 系统应提供退回历史查询功能，允许按调查期、企业名称等条件检索退回记录，并展示退回原因及处理状态，便于追溯与整改。

通知管理： 系统应支持市级用户发布通知信息，并提供通知浏览功能，使企业能够查看通知内容，包括标题、发布时间及详细信息，从而保证业务信息传达的完整性。

账户安全管理： 系统应提供密码修改功能，支持市级用户修改个人账户密码，并进行必要的安全校验；同时，系统应支持"忘记密码"找回功能，用户可通过输入账号、注册手机号或邮箱获取验证码，系统校验账号存在性后发送验证码，用户输入验证码及新密码即可完成密码重置，若验证码错误或超时则提示重新获取，连续多次输入错误验证码时将临时锁定找回操作。

通过本模块，省级用户能够实时掌握全省就业失业动态，及时发现数据异常，精准指导各市数据采集工作，确保向部级上报数据的准确性与时效性，并为政策制定提供可靠的数据支撑。

3.3.3 功能需求

数据汇总与修正： 系统应支持按调查期对各市上报数据进行统一汇总，并生成全省统计结果。针对数据质量问题，系统需提供数据修正功能，允许对明显错误数据进行修改，但必须保证原始上报数据不可被覆盖，修改数据需单独存储，并完整记录修改日志，以确保数据的可追溯性。

统计分析： 系统需支持多维度统计分析与图表展示，包括按地区、行业、企业性质等维度进行分析，并提供企业总数、岗位数、岗位变化量及占比等分析指标。系统应支持取样分析、对比分析和趋势分析，所有分析结果应支持导出为Excel文件。

数据上报： 系统需支持数据上报至部级系统，以及企业备案信息的审核处理。

通知管理： 系统应支持省级用户发布、修改、删除通知信息，并提供通知列表及详情查看功能。

数据质量监控： 系统应自动检测缺报、数据波动等异常情况并发出预警提示。

审计日志： 系统还应提供审计日志查询功能，支持按操作类型、时间、操作人等条件追溯关键操作记录。

账户安全管理： 系统应提供密码修改功能，并支持"忘记密码"找回流程：用户输入账号或注册联系方式获取验证码，验证通过后即可重置密码，连续多次输入错误验证码时将临时锁定找回操作，以保障系统安全性。

3.4.1 描述与优先级

该模块旨在为系统管理员提供集中、灵活、可审计的后台管理能力。其核心功能涵盖用户与角色的统一管理、上报时限的动态配置、系统运行状态的实时监控，以及操作日志的完整记录与查询等操作。

通过本模块，系统管理员能够高效维护系统用户体系，灵活配置业务规则，实时掌握系统运行健康状况，确保系统的稳定运行与权限分配的规范性。

3.4.3 功能需求
本模块需提供系统管理相关功能，包括用户管理、角色管理、上报时限管理、系统监控及操作日志管理等。

用户管理： 系统应支持对用户信息进行统一管理，包括用户的新增、修改与删除操作。在新增用户时，应支持填写用户基本信息并分配相应角色；在删除用户时，系统必须校验该用户是否存在已上报业务数据，若存在则禁止删除，以保证数据完整性。

角色管理： 系统应支持角色的创建、修改与删除，并允许为不同角色分配相应的功能权限。系统需预定义基础角色（省级用户、市级用户、企业用户等），并保证每个用户至少拥有一个角色。在删除角色时，若该角色已被用户使用，系统应提示并解除用户与角色的关联关系后方可删除，同时需为相关用户重新分配角色，以保证系统权限的有效性。

上报时限管理： 系统还需提供上报时限管理功能，支持新增和修改调查期时间范围，以控制企业数据填报周期。

系统监控： 系统监控功能需能够实时展示系统运行状态，包括CPU、内存、硬盘等资源使用情况，以便管理员掌握系统运行情况。

操作日志管理： 此外，系统应提供操作日志管理功能，记录系统级关键操作（用户登录、权限变更、配置修改等），并支持按操作类型、时间、操作人等条件进行查询与追溯。

【注】 本系统各功能模块优先级依据其对核心业务流程的影响程度划分：核心数据处理与决策支持功能优先级最高，数据采集与审核功能次之，系统支撑与管理功能优先级相对较低。

省级管理部门需向市级用户发布工作通知和任务指示。通知管理页提供发布通知的功能，省级管理员可创建和管理在线通知。页面包含"发布通知"模块，用户需输入通知标题、详细内容和选择接收对象（全部市级用户和企业、仅市级用户、仅企业用户、特定城市等）。页面下方提供两个操作按钮，"发布通知"按钮为青蓝色渐变背景，"保存草稿"按钮为深灰色，支持用户对通知内容进行编辑和预发布保存。已发布的通知自动推送至企业端用户的通知中心，确保重要信息的及时传达。
